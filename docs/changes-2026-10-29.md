# 2026-10-29：数据访问分层与聊天读取优化

本次发布相对主分支 `1a8f7ab`，包含已完成的消息检索契约调整，以及在该行为基础上实施的存储分层、读取优化和回归验证。下面分别说明对外行为与内部实现，便于回看版本变化。

## 解决的问题

之前数据库读写、JSON 编解码、消息窗口与索引协调主要集中在 `server_utils.py`。搜索和生成 Markdown 汇总时，即使不返回聊天原文，也会读取并解析完整 `raw_dialogue`；搜索还可能重复读取已经取得的主记忆。

本次将固定功能的数据访问集中管理，让不需要聊天全文的功能直接读取需要的字段，同时保留完整原文读取及现有写入协调机制。

## 内部实现

- `memory_domain.py`：纯规则，包含消息规范化、稳定消息编号、代表消息选择、上下文窗口和摘要处理；策略参数由调用方传入，不读取数据库或运行配置。
- `memory_store.py`：存储接口和 SQLite 实现，集中表结构、SQL、行映射、JSON 编解码和事务。路径由实例配置注入，便于使用临时库和未来替换实现。
- `memory_access.py`：业务读取函数，接受返回普通记录的读取函数，可使用内存替身验证，无需连接数据库。
- `server_utils.py` 保留兼容入口和写入、索引协调，新模块不反向依赖它。
- 默认搜索直接查询所需的物理表字段，不访问聊天原文列；复用已取得的主记忆，只补查缺失项。生成 `RAG记忆库时间线.md` 和获取可索引记录 ID 也使用轻量读取。
- 同一次详情请求，每个会话只读取、解码一次，再从同一份数据中选择多个锚点的上下文。不增加跨请求缓存。
- 若 `results.search_fields` 明确包含 `raw_dialogue`，搜索保留完整原文返回，避免将原来合法的配置静默改成空内容。
- 主记录与派生 `field_records` 仍在同一事务中提交，之后刷新 Markdown 和向量文件；跨进程锁继续覆盖整个写入协调过程。数据库事务不覆盖外部 FAISS 文件，原有重建与恢复机制继续负责它们。

轻量投影保留项目关联编号、中文标签与路径、项目摘要回退等字段语义；可索引 ID 仍遵循现有空检索文本过滤和稳定排序。

## 相对上一主分支的接口行为变化

这些消息检索调整在本次存储重构前已存在于工作区，本次一并发布其实现、配置、文档和测试。

- `search` 增加可选 `message_top_k`，省略或传 `null` 使用 `search.message_top_k`，配置缺失时默认 3。显式值必须为正整数，拒绝布尔值、浮点数和数字字符串。
- 聊天结果增加带评分的 `matched_messages`，`matched_message_ids` 与其严格对应。同一消息的多个切片取最高分，按记录内分差及位置间距选择代表消息，不改变主记忆排序和 `top_k` 的含义。
- 详情完整展开有效锚点的邻近窗口并合并去重，取消固定 40 条上限；旧 `results.max_total_messages` 配置被忽略。
- 只传主记忆 ID、未传有效消息锚点时返回末尾预览，默认最多 21 条；不会自动沿用上一次搜索的定位。`full_dialogue=true` 仍显式返回完整原文。
- 默认上下文视图保持只读，不能作为完整 `raw_dialogue` 回写。消息编号仅在所属会话内定位，不能假设全库唯一。
- 工具及参数说明同步解释主记忆数量、消息数量、预览与全文的区别。不新增专用会话查找 MCP 工具。

完整契约见 [检索与详情接口](retrieval-api.md)，实现分工及合成数据测量见 [数据读取说明](storage-access.md)。

## 验证记录

- 完整核心测试：76 项通过，使用默认 20 轮并发压力配置，覆盖 2／4／8 个独立进程保存、竞争更新、保存／更新／删除交错、后台重建及数据库锁等待。
- 随后补充的读取兼容与差分专项：6 项通过；其中 2 项为完整测试之后新增，合计覆盖 78 个核心测试用例。
- SQLite 列级检查禁止访问聊天原文列，同时禁止调用完整对话解码函数，默认搜索、Markdown 汇总和索引 ID 读取仍然成功。
- 比较五类记录的新旧读取字段、Markdown 输出及索引 ID 过滤和排序，结果一致；覆盖显式请求搜索全文的配置兼容分支。
- 验证主记录与派生记录一起提交或回滚、临时库路径隔离及每请求每会话单次解码。
- 并发测试的初始化超时、流关闭与失败清理调整一并纳入测试代码，便于复现本次验证。

所有测试使用临时数据；没有对正式记忆库执行迁移，也没有重新计算正式向量。合成读取测量只记录 Python 分配峰值，不代表进程总内存或稳定的性能提升比例。

可在安装项目依赖的 Python 3.10 环境运行：

```powershell
python -B -m unittest discover -s tests -v
```

默认并发压力测试会反复启动独立进程，耗时较长。日常开发可设置 `MEMORY_RAG_CONCURRENCY_ROUNDS=2` 缩短重复轮数；完整验证使用默认 20 轮。
