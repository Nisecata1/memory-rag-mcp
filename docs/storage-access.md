# 固定功能的数据读取与 Agent 自由查询

核心服务的固定功能通过 Python 内部函数读取数据。归档 Agent 可以直接用只读 SQL 探索数据库；这两种读取方式不必共用一组 MCP 查询工具。

## 核心服务的三个模块

- `memory_domain.py`：纯规则，包括消息规范化、消息编号、代表消息选择、上下文窗口与摘要规则。配置通过参数传入，不读取数据库或运行配置。
- `memory_store.py`：存储接口和 SQLite 实现，管理表结构、SQL、行映射、JSON 编解码及事务。数据库路径在创建实例时注入，不在导入模块时捕获。
- `memory_access.py`：详情与搜索的读取函数。它只接受返回业务字典的读取函数，能够用内存替身运行，不接收 SQL、连接或游标。

`server_utils.py` 继续保留兼容入口与写入、索引协调，使用当前配置创建存储实例。维护脚本和评测程序仍可通过旧入口配置临时数据库。新模块不反向导入 `server_utils.py`。

## 哪些地方需要完整聊天

| 功能 | 读取内容 |
| --- | --- |
| `search` | 轻量主记忆字段及命中检索切片；不加载整段聊天原文，已取得的主记忆不重复读取 |
| 生成 `RAG记忆库时间线.md` | Markdown 文本中实际使用的标题、摘要、标签和时间等字段 |
| 获取可索引记录 ID | 检索文本需要的字段，沿用现有空文本过滤和稳定顺序 |
| `get_details_by_ids` | 按类型批量读取详情；同次请求每个会话只解码一次，随后选择上下文或返回原文 |
| 保存、更新和重建消息切片 | 根据实际写入或重建需要读取完整原文 |

若旧配置明确把 `raw_dialogue` 放进 `results.search_fields`，搜索会保留完整原文返回，使用完整读取；默认配置不含该字段，使用轻量读取。这个兼容分支避免把原来合法的配置静默变成空正文。

详情默认返回只读上下文。只有 `full_dialogue=true` 才用于读取完整原文；上下文中的省略标记与 `context` 不能回写成完整聊天。

这次整理没有新增 MCP 工具，没有修改主库 schema、消息切片规则或向量签名。完整聊天继续以 JSON 文本存储。存储实现以后可以按实际需要使用 SQLite JSON 函数，归档 Agent 的只读 SQL 也可以查询嵌套字段。

## 写入顺序

主记录与相关 `field_records` 在同一数据库事务中提交；提交后才生成 Markdown 汇总并刷新向量文件。现有跨进程锁继续覆盖整个写入协调过程。数据库事务不承诺同时覆盖外部 FAISS 文件，原有重建与恢复机制继续负责它们。

## 归档 Agent

Agent 查看本地会话改动、自己查库并比较候选，确认来源后通过已有 `save_chatEvent` 或 `update` 写入。数据库结构说明、归档提示词和跨日期工作记录约定在相邻 `chat-archive-agent` 目录中维护；不为这些自由查询增加专用 MCP 接口。

## 合成数据读取检查

2026-10-29 在临时 SQLite 库中，用同一份虚构聊天分别执行完整读取和默认搜索的轻量读取。以下记录读取期间 Python 分配的峰值，单位 KiB，包含结果对象；它不代表数据库原生内存、进程总内存或整套检索的峰值。

| 消息数 | 完整读取 | 轻量读取 |
| --- | ---: | ---: |
| 1,000 | 1,788.7 | 26.0 |
| 10,000 | 18,034.6 | 22.1 |

这是单次合成样例，用于检查确实避开了大对话解码，不作为固定提升比例。自动测试同时在 SQLite 层禁止读取原文列，并禁止调用完整原文解码函数，验证默认轻量读取仍然成功；显式配置搜索返回原文时另测完整读取兼容分支。

日常开发回归可以设置 `MEMORY_RAG_CONCURRENCY_ROUNDS=2`，缩短并发用例的重复轮数；完整压力验证使用默认 20 轮。两种设置都仍覆盖独立进程并发，完整测试的耗时主要包括反复启动服务进程。
